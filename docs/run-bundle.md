# Run Bundle

Each `acta run` writes a local run bundle under `.acta/runs` by default.
On POSIX systems, this default runs root is Acta-owned: Acta creates it and
enforces mode `0700`, including tightening an existing default root. Newly
created custom runs roots are also `0700`. Existing custom roots retain their
owner-selected read and list permissions, so run names can be visible when the
root is listable; Acta rejects a custom root with group or world write bits
because those permissions weaken bundle integrity. Acta does not change an
existing custom root's permissions.

On POSIX, every run directory is owner-only (`0700`), and bundle artifacts are
written owner-readable/writable only (`0600`). Acta also tightens derived
artifacts when re-digesting an older bundle. These permissions reduce
accidental local exposure; callers must still treat bundles as sensitive and
control backups, uploads, and copies.

On Windows, Acta creates sensitive files with a protected DACL owned by the
current user and granting access only to that user, Local System, and built-in
Administrators. Root and run-directory access is likewise governed by Windows
ACLs rather than synthetic Go permission bits.

While an agent is running, raw output is held in an owner-only staging
directory under the user's cache, outside the workspace and declared writable
roots. The final run directory is published only after Acta has cleaned up the
platform process container. Windows Job Objects contain descendants. POSIX
uses a process group; a child that creates a new session or process group is
outside the portable guarantee. Cache
locations beneath the system temporary directory are refused; Acta uses an
owner-only home-directory fallback instead.

Commands that consume an existing bundle accept only bounded regular control
files resolving inside that bundle. Symlinks, FIFOs, devices, directories, and
replacement races are rejected before reading.

Example:

```text
.acta/runs/20260701T220000Z-codex-ab12cd34/
  run.json
  codex-events.jsonl
  codex.stderr.log
  event-times.jsonl
  digest.json
  acta-events.jsonl
  projection.json     # after acta digest re-projection
  workspace.diff
```

Claude runs use Claude-specific raw filenames:

```text
.acta/runs/20260701T220000Z-claude-ab12cd34/
  run.json
  claude-output.jsonl
  claude.stderr.log
  event-times.jsonl
  digest.json
  acta-events.jsonl
  projection.json     # after acta digest re-projection
  workspace.diff
```

## run.json

`run.json` is Acta-owned metadata for the subprocess run.

Current fields:

- `schema_version` - contract version; current writers emit version 3 and
  readers retain support for version 2
- `producer` - Acta producer name, version, commit, and build date
- `id` - run ID generated by Acta
- `trace_id` - optional OpenTelemetry trace ID when live export is enabled
- `agent` - normalized agent name
- `agent_version` - probed CLI version accepted by Acta's compatibility policy
- `cwd` - working directory given to the agent
- `base_commit_sha` - workspace HEAD commit at run start; omitted when the
  workspace is not a git repository, the repository has no commits yet
  (fresh `git init`)
- `base_branch` - workspace branch at run start, including on a not-yet-born
  HEAD; omitted when HEAD is detached
- `base_dirty` - present whenever the workspace is a git repository: true when
  it already had uncommitted or non-ignored untracked changes at run start.
  Acta's own bundle and staging directories never count as dirt. Absent means
  the workspace was not a git repository
- `head_commit_sha` - workspace HEAD commit at run completion; a value
  different from `base_commit_sha` means HEAD moved during the run — commits
  created by the agent, but a `git checkout`, `reset`, or `pull` moves it
  too. `workspace.diff` does not cover committed changes
- `model` - optional model override
- `repository` - optional repository display name such as `owner/name`
- `issue_number` - optional GitHub issue number used as the task basis
- `issue_title` - optional GitHub issue title used as the task basis
- `issue_body` - optional explicit issue body loaded from `--issue-body-file`
- `task_title` - optional display title from the issue title or explicit
  `--title`; prompts are never used as an implicit title
- `run_dir` - absolute run bundle path
- `recovery_dir` - populated only when final publication failed; points to the
  complete owner-only bundle retained for recovery (which may be staging or a
  private destination-side temporary directory)
- `command` - command shape Acta ran, with sensitive prompt text redacted where
  needed
- `started_at` - UTC start time
- `completed_at` - UTC completion time
- `duration_ms` - wall-clock duration
- `exit_code` - process exit code when available
- `ok` - the reconciled agent/evidence outcome. Required telemetry delivery is
  operational state: its failure leaves a successful `ok` unchanged, records
  `otlp_status: failed`, and makes the CLI return telemetry-only exit code 86
- `timeout` - true when Acta's timeout killed the run
- `termination_reason` - normalized final outcome such as `completed`,
  `timeout`, `cancelled`, `process_error`, `resource_limit`, `failed`, or
  `degraded`
- `error` - process error text when available
- `raw_stdout_path` - captured stdout path
- `raw_stderr_path` - captured stderr path
- `raw_stdout_artifact` / `raw_stderr_artifact` - portable bundle-relative
  artifact paths used by v2 readers
- `prompt_source` - `flag`, `args`, `stdin`, or test/internal source
- `prompt_captured` - true when explicit prompt retention was enabled
- `otlp_status` / `otlp_error` - distinguish not configured, not sampled,
  exported, and failed OTLP state for runs that started, including best-effort
  setup failures and all flush failures. Unsampled roots have no `trace_id`.
  Required delivery failure is reported after the agent outcome and bundle are
  durable, using telemetry-only exit code 86 when no other operation failed
- `raw_output_limit_bytes` / `raw_output_limit_exceeded` - effective combined
  stdout/stderr budget and whether it terminated the run
- `workspace_diff_limit_bytes` / `workspace_diff_limit_exceeded` - effective
  cumulative diff budget and whether final evidence crossed it
- `process_containment` - `windows_job`, `posix_process_group`, or the fallback
  `direct_process`, making the cleanup guarantee machine-readable
- `agent_config_mode` - `ambient_ephemeral`, `project_only_ephemeral`, or
  `authoritative_bundle`
- `runtime_bundle_sha256` - SHA-256 of the exact validated bundle bytes when a
  runtime bundle was used; its path and contents are not copied into metadata
- `reasoning_redaction_state` - `retained_local` when private reasoning remains
  only in raw/normalized bundle streams, `redacted` when its text was removed
  from persisted bundle artifacts, `failed` when redaction failed with the raw
  stream unchanged, or `partial` when an ambiguous commit could not be verified
  as byte-identical to the original stream
- `published_bundle` - optional digest-bound artifact reference written only by
  an Acta-owned publication path; launchers must not substitute agent output

## Raw Files

Within the configured combined raw-output budget, stdout and stderr are
preserved without interpretation by default. `--redact-reasoning` atomically
rewrites the stdout JSONL stream instead. Exceeding the budget fails the run.

For Codex, stdout is expected to be JSONL from `codex exec --json`.

For Claude Code, stdout is expected to be stream JSON from
`claude --print --output-format stream-json`.

## Git evidence semantics

`workspace.diff` combines staged, unstaged, and non-ignored untracked files.
Git-ignored files are not evidence. Acta excludes only the exact generated
run/control paths supplied by the runner; similarly named tracked paths such as
an unrelated `.acta` tree are not globally hidden. Diff generation uses a
private index snapshot and does not mutate the repository's real index.

If a workspace is recognized as a Git repository at startup, failure to
capture its final diff or HEAD is a run failure. Non-repositories remain valid
workspaces and omit Git fields.

## Compatibility and stability

Raw vendor output is immutable evidence: once recorded, no future Acta
version rewrites or annotates it,
which is what allows `acta digest` to re-derive artifacts from old bundles
with improved parsers. New capabilities add new files to the bundle (for
example, a rendered summary or an offline OTel trace export) rather than
changing existing ones when possible. Acta-owned JSON contracts are explicitly
versioned: optional additive fields may retain a schema version; removing or
renaming fields, changing types/meaning, or strengthening requirements bumps
the schema version. Readers reject future versions and normalize documented
legacy versions. See [Data contracts](data-contracts.md) and `schemas/`.

`acta digest` is transactional by default. A raw parse, event-timing, or
live-patch-preservation error exits 1 without replacing the existing derived
artifacts. `acta digest --allow-partial` explicitly accepts and writes the
degraded projection, emits a warning, and exits 0. Raw provider evidence is
never rewritten in either mode.

After re-digestion, `projection.json` is committed last as the completion
marker for the new derived generation. It records the schema version and Acta
producer plus SHA-256 hashes of `digest.json` and `acta-events.jsonl`.
Consumers that require a coherent re-projection should require this manifest
and verify both hashes. Initial `acta run` publication is already atomic at
the whole-directory level and therefore does not require the extra marker.

## acta-events.jsonl

`acta-events.jsonl` is Acta's stable product/replay event stream. It is
derived from `digest.json` and written as one JSON object per line with a
monotonic `sequence`.

Each event's `producer` identifies the Acta binary that recorded the immutable
run. Events rewritten by a later `acta digest` keep that original identity and
add `regenerated_by` for the binary that produced the new projection.

The event stream currently includes:

- `agent.prompt` when `acta run --capture-prompt` was explicitly enabled
- `run.started`
- `agent.message`
- `agent.reasoning`
- `agent.input`
- `agent.todo` / `agent.todo.updated`
- `agent.task.started` / `agent.task.progress` /
  `agent.task.completed` / `agent.task.incomplete`
- `agent.permission.denied`
- `agent.runtime.configured`
- `agent.output.structured`
- `agent.rate_limit.observed`
- `agent.error`
- `agent.lifecycle` for recognized provider lifecycle events such as thread or
  turn start/completion; the original provider event name remains in payload
- `agent.event.unsupported`
- `tool.call.completed` / `tool.call.incomplete`
- `tool.result.orphaned`
- `shell.command.completed` / `shell.command.incomplete`
- `web.search.completed` / `web.search.incomplete`
- `file.read`
- `file.written` / `file.write.incomplete`
- `diff.generated`
- `tokens.reported`
- `run.completed` / `run.failed`

Within the tested agent CLI ranges, any provider event Acta cannot normalize
is retained as `agent.event.unsupported` and makes the projection
degraded/non-successful. This prevents valid JSON from silently bypassing a
parser that has fallen behind the provider contract.

This stream is the intended bridge to backend ingestion and downstream replay UIs.
Raw vendor files remain the source evidence; `digest.json` remains the compact
summary/projection.

Primary events retain provider event names, lifecycle/status, identifiers,
tool server/name, bounded inputs/results, error details, web actions, and file
operation kinds when the provider emits them. Diagnostic events preserve
runtime/lifecycle/progress information and unknown provider events instead of
silently dropping them. Each normalized event links back to its source JSONL
line(s) through an artifact reference, while the immutable raw stream remains
available when a bounded normalized field was truncated.

`file.read` records repository-relative paths and structural spans. When one
provider result can be attributed to one file range without splitting or
guessing across combined command output, its `ranges` field also retains the
exact source text returned to the agent. Ambiguous multi-file results keep the
spans but omit range content.

`file.written` and `file.write.incomplete` may include `patches`, containing
the exact per-file unified diff observed between the provider's write-start
and write-result boundaries. These patches describe that write only; they are
not aliases for the cumulative `workspace.diff`. Text files larger than the
capture limit, binary files, private control paths, and writes whose boundaries
cannot be established retain their operation metadata without a patch.

`run.started` carries the task display metadata needed by live UIs:
`repository`, `issue_number`, `issue_title`, `issue_body`, `task_title`,
`cwd`, `base_commit_sha`, `base_branch`, `base_dirty`, `run_dir`, `agent`,
`model`, `command`, and `prompt_source`. The
`issue_body` field is present only when `acta run --issue-body-file <path>` is
used; Acta does not copy the normal agent prompt into this field. The
`base_*` fields follow the same presence rules as in `run.json` above, and
`run.completed`/`run.failed` carry `head_commit_sha`, so an events-only
consumer can detect that commits were created during a run without parsing
`run.json`.

Prompt retention is opt-in because prompts can contain credentials, private
repository context, or customer data. With `--capture-prompt`, the complete
submitted prompt is stored as the first `agent.prompt` event in
`acta-events.jsonl` and is uploaded with that stream in hybrid mode. It is
still excluded from `run.json`, command arguments, and process metadata.
Every prompt source is limited to 8 MiB and preserves its submitted bytes;
whitespace-only input is rejected. Issue bodies are limited to 512 KiB and
retained prompts to 1 MiB so generated
records and event lines remain readable by Acta's bounded replay and upload
paths.

Each encoded Acta event and each upload request is limited to 8 MiB. The
complete normalized stream is limited to 256 MiB, and a digest is limited to
100,000 timeline events / 64 MiB of normalized projection. Normalized strings
and tool payloads have smaller implementation limits and carry truncation
metadata; raw streams remain the evidence source. The CLI's combined raw
stdout/stderr budget defaults to 1 GiB. The workspace diff budget defaults to
256 MiB. Crossing either stops/fails the run instead of silently publishing
partial evidence; `0` explicitly disables the corresponding limit.

Live per-write snapshots also have a 64 MiB aggregate memory budget per run
and a 2 MiB patch budget per event. Crossing either evidence budget is recorded
and makes the run degraded/non-successful; it never silently omits patches from
an otherwise successful run.

## Timeout scopes

`acta run --timeout` measures only agent subprocess execution, beginning
immediately before process start. Git evidence operations have independent
30-second bounds and the agent version probe has a 5-second bound. Finalization
and hybrid upload are outside the agent timeout and surface their own failures.
`acta upload --timeout` covers preparation, hashing, requests, and completion.
Only `0` disables either user-configured timeout; negative durations are
rejected.

## Report Upload

When `acta run` is called with `--report-mode hybrid --backend-url <url>
--report-token <token>`, Acta uploads the completed bundle to the ingest
backend after local artifact generation succeeds. The upload uses the run id in `run.json`,
the events in `acta-events.jsonl`, and the terminal `artifact_refs` list from
the final `run.completed` or `run.failed` event.
`--report-token-env`/`--ingest-token-env` may be used instead of passing the
token value in argv; Acta reads the token and removes the named variable from
the agent subprocess environment.
Non-loopback upload endpoints must use HTTPS. Development environments on a
trusted private network may opt in to plaintext transport with
`--allow-insecure-http`; loopback HTTP remains available without the flag.
Upload API redirects are always rejected.

For production-scoped upload, pass `--run-id <id>` plus both
`--organization-id <uuid>` and `--repository-id <uuid>`, and pass a short-lived
scoped ingest token as `--report-token`. The launcher must mint the scoped token
for the same run id it passes to Acta. Acta creates the remote run as `running` first
and marks it terminal only after event and artifact upload succeeds, so an
interrupted upload does not look like a completed replay. An upload failure
makes the Acta command fail but does not rewrite the already-recorded agent
execution outcome, so the unchanged bundle can be retried with `acta upload`.

Hybrid upload is idempotent for events because Acta owns the monotonic
`sequence` values and the backend accepts duplicate `(run_id, sequence)` events
only when the content matches. Acta sends events in bounded batches and streams
artifacts from disk to the backend with `size_bytes` and `sha256` metadata instead
of base64-wrapping them in JSON.
Upload first pins one immutable event/artifact snapshot so concurrent local
bundle changes cannot mix versions. The total snapshot defaults to a 1 GiB
limit for both hybrid and standalone upload; `--max-upload-bytes 0` explicitly
selects unlimited preparation. Crossing the limit fails before a partial
success is reported.
Before creating the remote run, Acta validates the complete replay contract:
schema/source identity, consecutive sequences, optional prompt placement,
exactly one `run.started`, one final terminal event, and agreement between the
terminal event type and `run.json`.
Artifacts withheld because privacy redaction could not be verified remain in
the uploaded terminal `artifact_refs` manifest with `status: withheld`, a
reason, and `redaction_state: unverified`. Their bodies are not uploaded, so a
remote completeness check can distinguish them from genuinely missing
artifacts while replay keeps the original evidence reference.
